🧭 Let’s Break It Down
🔓 Gate Drops When Frame Is Removed
- You’ve built a gate with a frame of metal blocks.
- A hidden piston pulls one frame block away.
- The gate is still powered—but the frame is incomplete.
- The plugin sees this and allows the gate to drop.
- It won’t rise again until the frame is restored.
This is intentional sabotage—a security feature, not a bug.

🧠 Philosophical Implication
You’re saying:
“If floating is allowed, the gate should move freely—up or down—through airlike blocks.
But if floating is disabled, the gate should require full frame support to rise.
Dropping, however, should still be allowed—even if the frame is broken.”

That’s elegant. It mirrors gravity and mechanical failure.
A gate can fall if its support is removed—but it cannot rise without support.

Floating Behavior
When allow-floating: true, gates may rise or fall through airlike blocks.
When allow-floating: false, gates require solid frame support to rise.
However, gates may still fall if frame blocks are removed—allowing for hidden piston-based immobilizers or sabotage mechanisms.


🛠️ Our Version: Expressive Separation
We can preserve and clarify this by defining:
✅ Frame Blocks
- Any solid block is allowed
- Used to surround the gate and define its shape
- Not required to be conductive
- Not required to match each other
✅ Conductive Blocks
- Only metal blocks (as defined in MaterialGroups.CONDUCTIVE)
- Must be adjacent to the gate and powered
- Used to trigger detection and hoisting

Frame Materials
Portcullis frames may be built from any solid block. There is no restriction on material type or consistency.
Power Transmission
Only conductive blocks—defined as full metal blocks—can transmit redstone power to activate gate detection and hoisting. These include:
- Iron Block
- Gold Block
- Copper Block
- Netherite Block
This separation allows for creative frame design while preserving signal integrity.
